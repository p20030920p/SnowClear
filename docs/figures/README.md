# Result figures — interface

Every experimental result in this repository has a figure slot reserved for it. This file is the
single index of them: the READMEs carry only the captions, so nothing renders as a broken image
and the homepage stays short. Published figures are live in both READMEs already.

## How to publish a figure

1. Drop the file into this directory using the **exact filename** in the table below.
2. Add one image line at the matching caption in `README.md` / `README_CN.md` — each reserved
   slot ends with `Slot: \`docs/figures/<name>.png\``:

```markdown
![Per-scene precision, recall and F1](docs/figures/fig1_per_scene.png)
```

The READMEs carry only the captions, so the homepage stays short and nothing renders as a broken
image before the file exists. To list the reserved slots:

```bash
grep -n 'Slot:' README.md README_CN.md
```

Conventions: PNG, ≥ 1600 px wide, no transparency (GitHub renders on both light and dark
themes), one figure per result, caption text kept in the document rather than burned into the
image.

## Rendered algorithm (not a result figure)

| File | Shows | Regenerated by |
|---|---|---|
| `algorithm1_en.png` / `.svg` | Algorithm 1 with English annotations, referenced by `README.md` | `python3 tools/gen_algorithm_fig.py` |
| `algorithm1_zh.png` / `.svg` | The same algorithm with Chinese annotations, referenced by `README_CN.md` | same |

The algorithm is a figure rather than a fenced code block on purpose: a code block is rendered
with whatever monospace font the reader's browser picks, and a CJK annotation on the same line
destroys the column grid. The SVG stores its text as paths, so it cannot reflow either. Edit the
content inside `tools/gen_algorithm_fig.py` and re-run it — do not retouch the images.

## Published result figures

Panel sequence, colours and the metric callouts are produced by
`tools/render_qualitative.py`; every number printed in a panel is recomputed from the index
files, and the tool prints the same precision / recall / F1 the pipeline reports. The baseline
comparison runs the same way end to end: `tools/eval_baselines.sh` produces the per-scene CSVs,
`tools/gen_baseline_fig.py` turns them into Fig. 3 and Table 2, and `tools/render_baseline_clouds.py`
draws Fig. 12 through the same `render_hero3d.draw_scene` that draws the hero.

## What must not appear here

The dataset itself. Point clouds and their ground truth are not redistributable (see
[`../DATASET.md`](../DATASET.md)); figures may show rendered scans, but no figure may embed a
redistributable copy of the source data.

Numbers in the tables of `README.md` are the ones this repository can reproduce on its own data:
`tools/eval_baselines.sh` runs SnowClear and the compiled-in baselines over the reported set, and
`tools/gen_baseline_fig.py` produces Table 2 and Fig. 3 from the resulting CSVs, so neither is
retyped by hand. Cells that would need a third-party harness stay explicit `TODO`.
